# Nacre V8 / 0.9.0 contract

## Scope

V8 adds lexical list traversal, recoverable list extraction, and contact-book
search/filter/batch commands. It does not change the V7 ownership model.

## List traversal

```java
for (int number : numbers) { println(number); }
for (borrow Contact contact : contacts) {
    borrow Text name = contact.getName();
    name.print();
}
for (borrow mut Contact contact : contacts) { contact.setPhone(new Option<Text>.None()); }
```

- The collection expression is evaluated once and must name a stable owner or
  produce an existing borrow. Temporary owned lists are rejected.
- `int`, `boolean`, and `String` headers copy elements. Nominal object, enum, and
  interface headers explicitly use `borrow` or `borrow mut`; ownership is not
  extracted by traversal.
- Shared traversal holds a shared loan on the complete list root for the loop.
  Exclusive traversal holds an exclusive loan. Root-wide alias domains remain
  conservative, including lists stored in owned fields.
- Structural mutation, replacement, movement, or destruction through another
  alias is rejected while traversal is active. Exclusive element mutation is
  permitted through its iteration binding.
- The element binding is scoped to one iteration. `continue`, `break`, and
  `return` preserve cleanup and cannot retain an element into a later iteration.
- Traversal introduces no iterator allocation and no last-use lifetime inference.

## Recoverable list operations

| Operation | Elements | Success | Failure |
|---|---|---|---|
| `readonly Option<T> tryGet(int index)` | `int`, `boolean`, `String` | `Some` copy | `None` for invalid index |
| `Option<T> tryPop()` | All supported list elements | `Some` transferred last element | `None` for empty list |
| `Option<T> tryRemove(int index)` | All supported list elements | `Some` transferred element; remaining order preserved | `None` for invalid index |

Failure preserves list contents, size, and capacity. Success transfers affine
ownership exactly once; vacated slots no longer own a value. Returned options
are inline values and these operations add no allocation. Existing strict
`get`, `getRef`, `getMut`, `pop`, and `remove` retain their fatal-boundary contract.
There is no `Option<borrow T>` API in V8.

## Contact-book commands

- `search`: case-sensitive substring search over contact names, preserving
  original one-based positions. The query is entered at the following prompt.
  An empty query matches all contacts. UTF-8 bytes are compared without slicing
  inside a code point; no Unicode normalization or case folding is promised.
- `filter`: show contacts with a phone or without one, selected at a prompt.
- `remove-matching`: preview name-substring matches and remove them only after
  explicit `yes` confirmation. Cancellation, invalid confirmation, and EOF leave
  the book unchanged. Removal ends all preview borrows before structural edits
  and retains the order of survivors.

The existing validated candidate loading and atomic-save format remain unchanged.

## Explicit exclusions

First-class iterators, maps, closures, NLL, lifetime parameters, disjoint-field or
index borrowing, arbitrary partial moves, recoverable allocation failure,
exception unwinding, modules, threads, FFI, and a new compiler backend are not
part of this milestone. V8 does not promise a sandbox or cross-platform native
certification.

## Acceptance

Behavioral regressions and actual generated-program smoke runs must cover all
list representations, success/failure boundaries, traversal exits/nesting,
evaluated-once collections, rejected mutation/escaping references, and exactly-once
cleanup. Contact-book scenarios must demonstrate search/filtering, confirmed and
cancelled batch removal, save/reload, and malformed-load rollback. Run GCC and
Clang with ASan/UBSan, the existing suite, locked Rust 1.74 compilation, grammar
and editor packaging checks, actual editor syntax/diagnostic surfaces, and CI.
Publication contains curated portable sources only, not workstation paths,
process IDs, session-local evidence references, profiles, caches, or credentials.
