# Nacre V9 / 0.10.0 contract

## Bounded scope

V9 adds integer-keyed maps and a complete multi-file lending-desk application.
It preserves lexical lifetimes, conservative root-wide alias domains, native
C11 output, and the existing recoverable-error/ownership model.

## Map<int,V>

`Map<K,V>` is a reserved compiler-owned nominal generic. V9 accepts only `int`
for K; all signed int32 keys, including minimum/maximum, are valid. V supports
the same copied/owned representations as List: int, boolean, String, owned
classes, interfaces, inline enums, and collections. Borrows/local views cannot
be values, including nested view payloads.

| Method | Contract |
|---|---|
| `Map()` | Empty map; entries allocate only on first insertion |
| `readonly boolean containsKey(int key)` | Key presence, without retaining a reference |
| `readonly int size()` | Live entry count |
| `readonly boolean isEmpty()` | Whether the live count is zero |
| `Option<V> put(int key, V value)` | Copies primitives or consumes an owner. New key returns None; replacement returns the previous value in Some without destroying it |
| `Option<V> tryRemove(int key)` | Removes/transfers a present value in Some; absent key returns None without mutation |
| `readonly Option<V> tryGet(int key)` | Copied primitive values only; absent key returns None |
| `readonly borrow V getRef(int key)` | Shared affine-value access; missing key is fatal |
| `borrow mut V getMut(int key)` | Exclusive affine-value access; missing key is fatal |
| `void clear()` | Destroys remaining values exactly once and retains reusable entry storage |

Returned options are inline, not allocated wrappers. Replacement, lookup,
removal, and clear add no allocation; insertion may allocate for growth.
An unsuccessful removal/lookup preserves contents and size. Replacement never
grows the map. Growth relocates representations without destroying owners;
removed/replaced payloads have one transferred cleanup obligation.

The implementation uses a single entry buffer, open addressing, a deterministic
unsigned integer hash, power-of-two capacities, and backward-shift deletion.
No tombstone accumulation or separate key/value/state allocations are needed.
Allocation/size arithmetic is checked; allocation failure remains fatal.
Expected lookup/update cost is constant, with linear worst-case collision chains;
this is not an adversarial hash-flooding or sandbox guarantee. No ordering or
map iteration API is promised.

References retain a loan on the complete map root. Any conflicting insertion,
replacement, removal, clear, movement, or destruction is statically rejected,
even if a particular call would leave storage unchanged. Exclusive references
also block independent reads. Object pointers, inline enum slot addresses, and
interface fat pointers retain their existing ABI. Native enum tags/type IDs
come from specialization, not fixed backend constants.

## Lending desk

The application is a `nacre.json` source bundle under `examples/lending_desk/`,
not a module system. It starts empty and accepts one optional startup file path
through Args; all user data and paths come from input, not workstation constants.

- Books and tools implement Loanable, with polymorphic labels, availability,
  lending periods, detailed display, and record serialization.
- A generic Catalog<T> owns Map<int,T> plus an insertion-ordered ID list. Its
  borrowed getters derive from its receiver. Catalog instantiations in this
  application use nominal owned values, not unconstrained primitive borrowing.
- Members own a name and optional note. Resources own an availability enum:
  Available, Lent(member ID, due day), or Maintenance(owned reason Text).
- Resource/member IDs are positive and monotonically assigned. The native map
  itself remains unrestricted over signed int32 keys. The application uses an
  explicit non-negative logical day, not an unavailable wall-clock/date API.
- Commands: add-book, add-tool, add-member, list, members, show, lend, return,
  maintenance, rename, remove, remove-member, advance, load, save, help, quit.
  Rename offers replacement or append so both owned-field replacement and
  exclusive borrowed-return editing have a useful path. An empty maintenance
  reason releases a non-lent resource back to Available.
- Lending requires an available resource and an existing member. Return requires
  Lent. Lent resources cannot be removed or put under maintenance. Members
  referenced by active loans cannot be removed. Due-day and ID arithmetic is
  checked before mutation; invalid input and EOF during prompts do not partially
  commit a command.
- Listing uses borrowed ID-list traversal and shared map references. Mutation
  ends lookup/status loans first; sibling owned fields still share one root.
- Parsing uses Result and a local borrowed reader view; command dispatch uses a
  custom enum. Availability and optional notes are matched without consumption.

## Persistence

Use a versioned length-prefixed UTF-8 format. Store logical day, next resource
and member IDs, resource/member counts, resource kinds and fields, availability
and borrower/due-day fields, and optional notes. Text lengths count bytes and
must end on valid UTF-8 boundaries. Reject malformed numbers, overflow, duplicate
or non-positive IDs, inconsistent next IDs, unknown resource/state tags, missing
borrowers, invalid ranges, missing separators, and trailing data.

Construct and cross-validate a complete owned candidate before replacing the
current desk. Failed loading preserves the active state. Files.writeTextAtomic
provides atomic visibility, not crash durability or preserved permissions.
The exact format and command prompts belong in LENDING_DESK.md.

## Coverage and acceptance

Provide a feature-to-file/function matrix and rejected companion examples for
map aliasing/invalidation, escaping local-view borrows, and forbidden transfer
from borrowed values. Native scenarios must prove map replacement/extraction
across all representations, collision-chain deletion/reinsertion, growth,
signed-key boundaries, absence preservation, and exactly-once cleanup. Lending
scenarios cover all resource states, cancellation/error recovery, relationship
validation, Unicode/path-with-spaces save/reload, and malformed-load rollback.
Run GCC/Clang ASan/UBSan, the existing suite, locked Rust 1.74 compilation, bounded
fuzzing, editor/package checks and actual desktop acceptance, then private CI.
Publish curated portable sources only: no personal paths, credentials, profiles,
process IDs, cache files, or session-local evidence links.

## Excluded

Other map key types, custom hashing/equality, map traversal, first-class
iterators, lifetime/projection refinements, disjoint-entry borrowing, fallible
allocation, exception unwinding, modules, threads, FFI, and new backends.
The application is a working reference, not a claim to exercise every operator
or every invalid program inside its ordinary workflow.
